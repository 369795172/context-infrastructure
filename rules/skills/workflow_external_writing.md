# 外部写作与成文工作流

> [!IMPORTANT]
> **在采取任何写作或处理行动之前，Agent 必须完整阅读本文件直至文件末尾（EOF）。**
> 全局权限边界与不可逾越的执行合同已在首屏明确规定，后续的阶段性参考指南仅作为渐进披露的具体细节，不能覆盖或修改本章的约束。

## 元数据

- **类型**：工作流（Workflow）
- **适用场景**：将经过验证的调研素材撰写为面向零共享上下文读者的分析文章、公开调查报告、客户内容或外部课程材料。
- **前置依赖**：调研阶段的产出，或同等效力的素材包（Source Pack）。
- **适用角色**：Manager（管理与审计者）、IC-1/IC-2/IC-3（各个阶段的独立会话作者）。
- **默认产出**：`contexts/survey_sessions/`；只有用户明确要求博客时才写入目标项目的博客目录与格式。
- **最后更新**：2026-07-20

## 0. 不可覆盖的执行合同

本节规定了本项工作流中最高优先级的执行合同。任何局部指令、历史版本、以及具体的阶段性指南，若与本节冲突，均以本节为准。

1. **IC-3 是唯一最终文本权威。** 最终的标题、正文、标点、链接锚文本、图片引用以及图片说明文字（alt text）必须完全来自一份通过验收的 Antigravity 完整输出。任何其他角色或阶段均无权对文本进行二次改写。
2. **Manager 对最终文本的修改权为零。** Manager 负责研究、编写设计简报、生成配图、进行只读审计、复制文件和运行验证，但绝不能修改 IC-3 候选文本中的任何字符。拼写、事实、链接或格式问题均不得由 Manager 直接在候选文本中修补。Manager 的任何手动编辑都将被视为对最终文本主权的侵犯。
3. **问题通过完整重写闭环解决。** Manager 发现问题时只负责编写只读审计报告，并启动全新的 Antigravity 会话。新会话需读取设计简报、原始素材包、上一版完整候选文本以及最新的审计报告，从空白页开始输出完整的新候选文本。禁止通过拼接不同版本或应用局部补丁来完成修改。
4. **图片契约在 IC-3 前冻结。** 最终的图片文件名、相对路径、文中引用位置以及每张图表达的语义意图必须在设计简报中确定。IC-3 负责将最终引用写入正文。此后，Manager 只能复制图片文件，绝对不能修改正文中的 Markdown 路径。
5. **阻塞性问题未解决前不得交付。** 只有当理解门控、认知舒适度门控、事实边界、结构连续性、配图以及确定性检查全部通过，且自审报告中没有阻塞性问题时，候选文本才允许归档。每个任务最多自动执行三轮修订，若三轮后仍未通过，必须保留所有中间工件并向用户报告具体阻塞。
6. **归档必须直接复制并验证。** 最终交付的归档文件必须与选定的候选文本在字节级别上完全一致。不存在任何比例的修改容忍度，也不允许任何词级或机械执行的例外情况（通过 `cmp` 命令或哈希值进行验证）。
7. **写作与发布分离。** 本工作流的终点为本地可交付文件。任何博客部署、外发邮件、社交媒体发布等操作，均需要获得用户的明确授权。
8. **短文或快速草稿的例外限制。** 篇幅少于 1000 字的文章或用户明确要求的快速草稿可以跳过 IC-2 阶段，但绝不能跳过 IC-3 阶段、Manager 的只读验收以及最终的字节级别比对。

## 1. 路由与适用场景

本工作流用于面向外部读者的成品写作。对于用户本人、内部协作者或未来 Agent 阅读的内部文档，应使用[内部写作工作流](./workflow_internal_writing.md)。

外部文章必须确保零背景读者在首次接触公司、产品、事件或技术术语时就获得充足的上下文。零背景意味着读者的理解不依赖当前对话、素材包或作者旧文所提供的隐含前提。

本工作流不对读者做任何先验假设。读者被视为具有基本通识但对当前项目、技术细节、内部决策或组织架构一无所知的外部主体。因此，行文的清晰度与解释的完备性是第一优先级。

如果读者必须了解先前的背景或特定的编辑讨论才能看懂某段论述，则该段落未达到外部写作的要求。Manager 在评估文章性质后，应当将外部受众的文章路由至本工作流，并将局部阶段的执行细节分发至对应的参考文件。对于字数极少、结构极其简单的短文，虽然可以在用户授权下跳过 IC-2 阶段，但底线门控和字节比对契约依然保持最高约束。

## 2. Thesis 挖掘门控 (Thesis Mining Gate)

在进入正式写作设计（Reasoning 阶段）之前，必须通过 Thesis 挖掘门控以确保文章具备扎实的核心论点：

- 如果用户未提供明确的核心论点，或者现有论点尚未经过充足的证据与反方压力测试，必须首先运行 [Thesis Mining](./workflow_external_thesis_mining.md)。
- 它读取相关输入并产生临时决策文件 `tmp/<session_slug>/thesis_decision.md`。
- 只有当其判决（Verdict）为 `PROCEED` 时，才允许创建设计简报 `writing_brief.md`。
- 若判决为 `DO_NOT_WRITE_YET`，代表当前素材或论点无法支撑一篇外部文章，应停止写作或补充缺失证据，绝对不能为了完成任务而强行编造论点。
- 如果用户已提供明确论点，则保留其写作方向，但仍需对其进行证据、边界、最强反方、既有观点连续性以及读者增量（Reader Delta）的压力测试，检查结果需记录在简报中。

## 3. 阶段与阅读顺序地图

在整个写作生命周期中，参与各方必须按照以下地图中规定的顺序逐步推进任务，并确保在进入下一阶段前完全满足当前的退出门控：

| 阶段 | 执行角色 | 必读文件 | 核心产出 | 退出门控 |
| :--- | :--- | :--- | :--- | :--- |
| **Preflight** | Manager | 本文件、COMMUNICATION.md、bestpractice_external_prose.md | 路由与任务边界 | 确认外部属性、输出位置和发布限制，确保流程不越界 |
| **Thesis Mining（按需）** | Manager | [Thesis Mining](./workflow_external_thesis_mining.md) | `thesis_decision.md` | 需要挖掘或压力测试 thesis 时，verdict 必须为 `PROCEED`；`DO_NOT_WRITE_YET` 则中止或补齐证据 |
| **Reasoning** | Manager | [结构指南](./reference_external_reasoning_structure.md)、素材包、旧文 | 设计简报、口吻校准 | 确定核心论点、论点依赖图、概念引入与图片契约 |
| **IC-1** | 全新 AGY 会话 | 设计简报、素材包、[Antigravity CLI](./antigravity_cli.md) | 结构稿 | 结构与证据齐备，此时不追求成稿声线与微观句式 |
| **IC-2** | 全新 AGY 会话 | 设计简报、结构稿、校准集、[口吻指南](./reference_external_voice_rewrite.md)、[Antigravity CLI](./antigravity_cli.md) | 重写稿 | 概念引入自然，通过认知舒适度与章节交接检查 |
| **Image Freeze** | Manager | 设计简报、结构稿、[交付指南](./reference_external_delivery_checks.md) | 最终图片文件 | 图片文件名、路径、位置与意图完成冻结，锁定视觉契约 |
| **IC-3** | 全新 AGY 会话 | 设计简报、素材包、重写稿、校准集、冻结的图片契约、[QA 指南](./reference_external_prose_qa.md)、[Antigravity CLI](./antigravity_cli.md) | 完整候选文本、自审报告 | 通过理解与认知舒适度双门控，自审报告中无阻塞性问题 |
| **Acceptance** | Manager | 设计简报、素材包、候选文本、自审报告、[交付指南](./reference_external_delivery_checks.md) | 审计报告或通过结论 | 只读回归检查与事实核对全部通过，审计状态为 PASS |
| **Delivery** | Manager | 验收通过的候选文本 | 最终文件与图片 | 完成复制与字节比对，使用 `read` 工具在客户端触发最终版本渲染 |

## 4. 核心工件列表

所有中间工件应统一保存在临时会话目录 `tmp/<session_slug>/` 中，通过明确的版本号进行归档，确保整个修改历史可追溯，并方便全新的写作会话随时拉取参考：

- `source_pack.md`：记录事实、原始链接、引用边界与不可更改的专有名词。它是成稿的权威事实边界，正文不得引入其中没有覆盖的新事实。
- `writing_brief.md`：规定读者起点、目标信念变化、因果模型、证据角色、概念引入规划以及图片契约。这是指导后续所有写作阶段的最高大纲。
- `style_calibration.md`：包含 3 至 5 篇同渠道正向样本、可继承的口吻特征、教材端与表演端的负面示例。用于确保文章声线不偏离目标渠道风格。
- `article_structural.md`：IC-1 生成的结构稿，标记了结构信息与证据位置，用于锁定文章的逻辑框架。
- `article.md`：IC-2 重写后的成稿，解决了名词引入和认知连贯性的问题。
- `article_final_vN.md`：IC-3 产出的完整候选文本，作为唯一的交付物候选。
- `prose_qa_vN.md`：IC-3 提交的自审报告，详细记录了各项门控与审查维度的核对结果。
- `content_audit_vN.md`：Manager 编写的只读审计报告，用于指出问题和允许的修改方向。

## 5. 统一 Go/No-go 门控

候选文本只有在完全满足以下条件时才允许交付。Manager 在进行只读审计时，应当对以下门控逐项核对，不允许存在任何模糊空间：

1. **首屏合同**：标题与首屏让读者立即明白讨论对象、核心判断以及继续阅读的增量价值。
2. **核心论点**：文章包含唯一具体且可反驳的核心论点，并在前 25% 的篇幅内清晰呈现。
3. **概念引入**：每个概念在首次引用前均已获得足够上下文，不依赖读者的隐含前提。
4. **依赖顺序**：每节沿着读者的问题推进，依赖项先于论点出现。遮住标题后，相邻章节仍能自然衔接。
5. **认知负荷**：读者不需要同时记住多条尚未落地的分类。对于三个或更多实际替代方案，必须提供局部地图，说明总数、共同标准和相互关系。
6. **声线平衡**：文字介于教材腔与表演式口语之间，分析框架不进入面向读者的正文。
7. **事实边界**：所有事实、数字、归因、链接和论点强度均在素材包边界内。
8. **配图合规**：配图有效降低了认知负担，且其引用、格式和大小符合交付规范。
9. **QA 结论**：自审报告中显示理解门控（Comprehension Gate）与认知舒适度门控（Cognitive Comfort Gate）均已通过，且没有发现阻塞性问题。
10. **字节一致**：最终归档文件与通过验收的候选文本在字节级别上完全相同。

## 6. 失败与返工状态机

IC-3 可以在不改变论点、论点图、事实边界与章节依赖的前提下对正文进行重新润色。如果 IC-3 发现必须增加新事实、改变核心论点、重排主要章节或重构证据链，则不应该自行修改，而是必须在自审报告中标记阻塞（BLOCKER），说明具体位置与依赖缺口。

Manager 发现任何问题时，必须将其记录到只读审计报告中，指出原句、失败的门控以及允许的修改方向，不得在审计报告中直接给出修改好的替代段落。随后，启动全新的 AGY 会话从头生成新候选文本。

状态机转换具体规定如下：
- 若任意门控失败，Manager 记录审计报告，启动下一轮 IC-3。
- 若达到第三轮依然存在阻塞性问题，必须立即停止生成，保留现有全部工件并向用户汇报失败原因。这可以防止 Agent 陷入无休止的机械自我重复循环。只有当用户重新校准简报、调整素材包或提供新指示后，才能重新启动第四轮。
- 若全部门控通过，且审计报告状态为通过，则允许进入归档和交付。

## 7. 微观语言与格式约束

在撰写任何本工作流及参考指南相关的文档时，必须遵守以下微观中文质量底线：
- **主动语态优先**：凡是动词去掉“被”字句子依然通顺的地方，一律去除被动句式，改用主动表达。
- **句子节奏自然**：避免在单个句子中堆砌多个动作或层叠定语。通过短句阐明核心判断，通过长句连接因果、证据与限制。
- **清除评价标签**：严禁使用“很直接”、“很透彻”、“非常清晰”等自我主观评价字眼，用客观的事实、数据与边界来说话。
- **禁止使用破折号**：正文中不得使用中文破折号（“——”）来做情绪停顿或转折，改用自然的逗号、括号或分号进行连接。
- **括号使用规范**：禁止使用无信息增量的中英文双语对照括注，仅在首次提及专业特有术语且确实有必要时使用括号包裹英文原词。
- **专有名词一致**：在全文范围内，专有名词（如产品名、API 标识符、模型名称等）的拼写、大小写必须与素材包完全保持一致。

## 9. 本地交付终点

最终的 Markdown 文件与图片将保存在工作区中。在完成最后一次写入后，Manager 必须使用 `read` 工具读取最终的 Markdown 文件，以在客户端触发渲染。最后向用户回复文件路径与已知的残留风险。在未获得明确授权时，不执行任何外发动作。

在完成归档前，Manager 必须确保本地交付文件的内容与通过验收的候选文本完全一致，并且没有任何内部调试痕迹或未完成的占位符残留。
