# 外部写作：配图、检查与交付指南

> [!NOTE]
> **适用阶段**：供 **Manager** 在 **Image Freeze**、**Acceptance** 以及 **Delivery** 阶段阅读使用。
> 本文件所涉及的权限边界与交付合同，始终以 [外部写作与成文工作流](./workflow_external_writing.md) 的第 0 节为准。本指南仅提供具体的阶段性执行细节，不授予 Manager 任何对最终正文的修改权限。

## 配图契约与规范

文章中的配图必须切实降低读者的认知负担，而不能仅仅起到装饰性作用。篇幅在 2000 字以下的文章至少需要包含一张配图，2000 字及以上的文章通常需要配置 2 至 3 张配图。

- **格式与来源**：最终嵌入正文的图片文件必须使用当前工作区中可用的图像生成或重绘工具生成或重绘，并采用目标渠道支持的 PNG、JPG 或 WebP 格式。
- **草稿重绘**：使用代码工具、流程图工具或演示文稿工具导出的结构草图仅能作为重绘的输入源，绝对不能直接写入最终的 Markdown 交付文件中。
- **数据合规**：定量图表必须先通过可验证的数据处理方法确定其数据结构，然后再交由工作区中的图像生成或重绘工具进行视觉重绘，以保证数据精确度。
- **视觉风格**：默认采用浅色背景、低饱和度、简洁的研究报告设计风格。应避免使用霓虹灯效、发光阴影以及没有任何实际信息的纯装饰性元素。
- **尺寸与体积**：图片最终需要压缩为 JPG 或 WebP 格式，长边控制在 1024 像素以内，单张图片体积小于 200 KB，正文中禁止使用 base64 编码嵌入图片。
- **流程节点**：图片文件名、相对路径、文中引用位置以及每张图需要表达的语义意图必须在 IC-3 阶段开始前完成冻结。IC-3 根据该意图写出最终 alt text 和图片引用。此后，Manager 只能将图片文件复制到目标目录，绝对不能修改 Markdown 中的图片引用路径或 alt text。

## 确定性回归检查

**确定性扫描仅具诊断性：正则命中并不自动等同于错误，且绝不授权 Manager 修改正文。** 当扫描命中时，Manager 应当结合上下文进行语义判断。如果命中项确实构成理解或质量问题，Manager 应当将该问题记录到审计报告中，将其视为阻塞性问题（BLOCKER），并以此进入下一轮 IC-3 会话。

回归扫描的命令行示例如下：

```bash
# 检查内部脚手架或元数据泄露
rg -n 'L[0-8]|axiom|Phase [A-Z]|Thesis Catalog' <candidate>

# 检查无信息增量的双语括注
rg -n '[\p{Han}”’」』][（(][A-Za-z][A-Za-z0-9 _./+:-]{1,50}[）)]' <candidate> | rg -v 'https?://|!\['

# 检查常见的中英文混排残留词汇
rg -n '\b(of|and|the|to|in|for|with|or|but|is|are|was|were)\b' <candidate> | rg -v 'https?://|!\[|^\s*#|^\s*>'

# 检查图片引用与说明文字格式
rg -n '!\[[^\]]+\]\([^\)]+\)' <candidate>

# 检查机械的排比句式（如“可X、可Y、可Z”）
rg -n '可[\p{Han}]{1,6}[、，,]\s*可[\p{Han}]{1,6}([、，,]\s*可[\p{Han}]{1,6})?' <candidate>
```

此外，Manager 必须机械核对候选文本与素材包中声明的数字、链接、图片路径以及二级标题的顺序。凡是未经回归检查的文本，一律不得视为通过验收。

## 归档协议

归档操作必须严格遵守以下步骤：

1. **选择候选版本**：从历史候选文本中，选择一份通过了全部门控验收的完整文本。
2. **直接执行复制**：直接将该文件复制到最终的可交付路径中。在此期间，不得进行任何模板替换、路径修复或格式化调整。
3. **一致性校验**：在终端运行 `cmp -s <agy_candidate> <final_md>` 对比两者，或分别计算两者的 SHA-256 哈希值，确保两者完全一致。
4. **差异处理**：如果比对结果存在任何差异，均视为交付失败。此时必须重新执行直接复制，不得对差异进行任何人工改写或修补。
5. **配图校验**：验证最终图片文件在目标目录中确实存在、格式正确、尺寸和大小符合规范，且 Markdown 文件中的每个相对路径均可以正常解析。
6. **触发渲染**：使用 `read` 工具从最终 Markdown 文件的开头读取足以覆盖全文的内容，确保在客户端成功触发最终版本的渲染。

## 最终交付检查清单

在宣布交付完成之前，Manager 必须确认以下条件全部满足：

- 最终的 Markdown 文件与选定的候选文本在字节级别上完全一致。
- 正文中的所有链接、图片路径以及本地路径均可以正常解析。
- 最新的一版审计报告状态为通过（PASS），且没有任何未解决的阻塞性问题。
- 所有的临时提示词、会话日志、素材包、审计报告等内部或私有资料均留在临时目录中，未误上传至公开目录。
- 最终回复中向用户提供具体的文件路径以及任何已知的残留风险。
- 在未获得用户新的明确授权之前，绝对不执行博客部署、社交媒体发帖、邮件发送等外发或发布动作。
