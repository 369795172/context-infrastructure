# 外部写作：成稿重写与声线校准指南

> [!NOTE]
> **适用阶段**：供 **IC-2** 会话以及 **Manager** 准备对应提示词（prompt）时阅读使用。
> 本文件所涉及的权限边界与交付合同，始终以 [外部写作与成文工作流](./workflow_external_writing.md) 的第 0 节为准。本指南仅提供具体的阶段性执行细节，不授予 Manager 任何对最终正文的修改权限。

## IC-1 结构稿的承接

IC-1 读取设计简报和素材包，输出结构稿 `article_structural.md`。结构稿负责将核心论点、论点依赖、证据位置、反方边界、概念引入、链接、数字和图片占位符放置到正确的章节中。结构稿的每一节都需要标明读者的问题与具体的可观察后果，但不追求可发布的最终文本质量。

结构稿绝不能写成讲义式的半成品。结构稿可以显式暴露结构信息供下一阶段使用，但必须向 IC-2 明确：IC-2 阶段仅继承结构稿中的主张、证据、链接、数字、章节依赖以及图片契约，而不应继承结构稿的句式、段首和叙述节奏。

## 校准集配置

在启动 IC-2 阶段前，Manager 应当从相同的发布渠道中，选择 3 至 5 篇近期发布的、经过明显人工打磨且解释难度相近的优秀文章，并将其记录在 `style_calibration.md` 中。校准集必须包含以下内容：

- 样本路径以及最值得参考的 1 至 3 个段落。
- 应当继承的叙述距离、事实到判断的切入方式、概念的解释风格以及句子的节奏。
- 严禁复制的特定比喻、句式、章节结构以及第一人称的使用位置。
- 从当前结构稿或历史失败稿中挑选出 2 至 3 段教材腔的负面示例，以及 2 至 3 段表演式口语的负面示例。

Manager 绝对不能只按日期机械地收集样本，也不能只给出抽象的风格规则而不让 Agent 阅读具体的优秀成稿。

## IC-2 重写任务

IC-2 需要从空白页开始完整重写，生成 `article.md`。重写的目的并不是简单地把书面词汇替换成口语词汇，而是让一个真正理解问题的人，顺着读者的疑问，自然地介绍自己的发现。

合格的文章声线应当处于以下两端之间：

- **教材腔失败表现**：一上来就宣布主题、依次定义每个名词概念、在每一节的结尾使用抽象的总结句。
- **表演腔失败表现**：过度依赖大巴车、战争、盖房子等装饰性的比喻，或者频繁使用网络流行词汇、俚语来刻意拉近与读者的距离。
- **理想状态**：先描述具体的对象如何做事，随后带出核心判断。第一人称只用来承担真实的观点判断，不承担情绪化的表演。

## 降低读者认知负担

为了贯彻低认知负荷的原则，重写时必须遵守以下具体方法：

1. **动作先于分类**：先展示同一任务在不同方案下的具体执行过程，然后再总结它们之间的差异。
2. **案例贯穿始终**：在跨章节对比同一组抽象对象时，尽量沿用同一个请求、工单、人物或运行记录。
3. **延迟术语命名**：先描述读者能观察到的具体动作，等机制清晰后再对组件或模式进行命名。
4. **单段聚焦单一关系**：拆分段落后，每一段的入口必须从读者已经熟悉的对象或概念切入。
5. **角色、定义与影响同步到达**：当新术语、指标或数字首次出现时，读者应当能立即回答它描述了什么、统计了什么，以及它会改变谁的结果。
6. **局部地图规则**：当遇到三个或更多实际替代方案、步骤、状态或风险时，在它们出现之前，必须向读者说明总数、共同的划分标准以及相互关系。
7. **完整因果链条**：每个章节需要完整交代面临的问题、明显的替代方案、当前的运行机制，以及当前机制解决不了什么。如果确实没有自然的替代方案，不要强行编造。
8. **交接对成对设计**：章节之间的衔接应当采用成对设计，例如：使用同一个任务进入下一个动作、让当前的机制暴露其边界，或者利用前一个选择所产生的后果来自然过渡。

定义齐全并不等同于阅读顺畅。如果发现读者需要在脑海中同时维护多条抽象的线索，应当将这些信息重新整理成一个线性展开的过程，让概念依次自然出现。

## IC-2 阶段自检

IC-2 完成正文重写后，必须对照以下标准进行自我检查：

- 大声朗读开头三段和每个二级标题（H2）的第一段，重写任何读起来像论文摘要、产品说明书、新闻通稿或课程讲义的段落。
- 从零背景读者的视角出发，检查每个概念首次出现的位置，优先补充动态过程和动作，而不是字典式的定义。
- 将生成的成稿与校准集进行盲读对比。如果成稿明显更像一份冷冰冰的说明书，不得以“写作更规范”为借口放行。
- 删除所有必须依赖比喻和俚语才能成立的解释，恢复具体的底层运行机制。
- 遮住所有的二级标题，检查相邻章节之间是否依然能够自然连接。
- 读完每一节的第一段后，检查是否能在不使用新术语的前提下，向他人复述清楚本节中谁做了什么，以及哪里发生了变化。

IC-2 输出的内容依然不是最终的可交付版本。它必须完整保留设计简报中约定的核心论点、论点依赖图、事实边界、链接、数字以及图片契约，为后续全新会话中的 IC-3 提供可靠的输入。
