# 外部写作：确定论点与结构指南

> [!NOTE]
> **适用阶段**：由 **Manager** 在 **Reasoning** 阶段及编写 `writing_brief.md` 时阅读使用。
> 本文件所涉及的权限边界与交付合同，始终以 [外部写作与成文工作流](./workflow_external_writing.md) 的第 0 节为准。本指南仅提供具体的阶段性执行细节，不授予 Manager 任何对最终正文的修改权限。

## 核心论点发现

核心论点（Thesis）是文章的灵魂。当用户给出了明确的核心论点时，应当保留其基本判断，重点检查证据能否支撑该论点，以及该论点与作者既有观点是否具备连续性，避免重新发明写作方向。当用户尚未给出核心论点时，Manager 应当按照以下步骤进行探索：

1. **查阅论点目录**：从论点目录文件中选择 1 至 3 个相关的分析视角作为启发，但不得生搬硬套既有框架。
2. **检索历史背景**：根据产品名称和核心问题，搜索作者的旧文、公理库以及相邻的公开文章。
3. **定位文章坐标**：判断新文章是在补充既有空白、修正旧有判断，还是在提供相反的例证。
4. **形成可反驳的核心判断**：撰写出一个具体且读者能够同意或反对的核心论点，并拆解出 3 至 7 个具有明确方向的因果关系主张。

**禁止将分析透镜转化为核心论点。** 当编辑要求按照时间、维度或特定顺序检查素材时，必须先在头脑中过滤掉这些方法论层面的词汇，检查去掉它们后是否留下明确的、面向读者的实质性判断。只有这些实质性的判断才能作为文章的核心论点，而时间线和分类矩阵只能作为组织证据的辅助方式。

## 设计简报契约

设计简报（`writing_brief.md`）是后续所有写作阶段的权威指导文件，必须包含以下核心要素：

- **读者起点状态（Reader Start State）**：明确说明读者原本如何理解讨论对象，以及他们缺少哪些必要的前提知识。
- **目标信念变化（Target Belief Change）**：用一句话概括读者的核心理解应当从什么转变为什么。
- **因果模型（Causal Model）**：列出 3 至 7 个具有明确因果方向的主张及其相互依赖关系。
- **证据角色（Evidence Roles）**：明确每份核心证据的具体职责，说明它们是负责建立旧有模型、证明最新变化、解释具体机制、验证核心判断，还是用于限制结论的外推边界。
- **概念引入规划（Concept Introduction Plan）**：列出每个陌生名词或术语首次出现的位置，以及读者在看到该词之前需要获得的上下文准备。
- **不可更改的专有名词（Immutable Terms）**：列出必须保持原样的产品名、模型名、API 标识符以及极易翻译错误的术语。
- **图片契约（Image Contract）**：明确每张配图所要压缩或解释的机制、最终图片文件名、相对路径、文中引用位置以及图片的语义意图。

没有明确证据角色的素材一律不得写入正文。简报所提供的上下文应当仅为核心论点成立所需的最小因果模型，不应承担百科全书式的综述功能。

## 叙述设计路径

叙述设计路径（Voice Route）是关于如何向读者层层展开故事的设计，而非简单的文章提纲：

1. **寻找核心反差**：发掘本篇中最为独特、最值得主动讲给朋友听的反差、异常或变化。
2. **阐明作者动机**：说清作者为什么在意这个问题。在没有真实判断时，不要强行使用第一人称。
3. **模拟读者追问**：明确每一节读者会自然产生什么疑问，以及前一节是通过什么动作、限制或后果将读者引向当前章节。
4. **确保动作落地**：每一节必须包含至少一个可观察的动作或后果。
5. **设定口吻红线**：针对本篇主题，分别列出 3 至 5 个容易出现的教材式句式和表演式口语，作为后续阶段的避雷线。
6. **选取贯穿案例**：当需要在多个章节之间对多个抽象对象进行比较时，必须选取一个具体的案例贯穿始终。
7. **局部地图例外**：对于三个或更多实际替代方案、步骤、状态或风险，在它们出现之前，必须向读者说明总数、共同的划分标准，以及它们之间是替代、递进还是阶段性的关系。这属于必须提供局部地图的例外规则。

分析框架与面向读者的桥梁必须明确分开。虽然四问、五层、三维度和分类矩阵能够帮助作者理清思路，但只要读者在实际操作中不需要用到这些框架，正文就应当沿着具体过程来展示差异，等具体的动作出现之后再进行命名。

## 依赖关系检查

在进入 IC-1 阶段之前，Manager 必须对照以下问题逐节进行核对：

- 本节具体改变了读者哪一项既有理解？
- 本节所需的概念和事实在此之前是否已经出现并解释清楚？
- 是哪一个已经出现的对象、动作或后果在承载本节的讨论？
- 是否要求读者在脑海中同时记住多个尚未落地的新概念？
- 当出现三个以上并列项时，是否提前给出了局部地图？
- 本节第一段是否实际接住前一节末尾留下的悬念或对象？

如果第一问没有明确答案，说明该章节冗余，应当直接删除或合并。如果依赖的前置概念尚未出现，应当重新调整结构顺序，而不是依靠在正文中临时插入定义句来修复。如果章节之间的交接失败，应当成对设计前一节的收尾与后一节的入口。

## 标题设计

标题是作者与读者之间签订的最短阅读合同，必须让读者一眼确认讨论对象、相关性以及分析的增量价值。如果对象对读者而言比较陌生，标题中应当带出其所属的类别、核心动作或重大变化。对于事件驱动的文章，原则上应当提及新闻事件的对象。准确性应当优先于悬念，严禁使用可以套在多篇文章上的万能模板。

在编写简报时，应当从不同的判断角度设计出 3 至 5 个候选标题。随后与同一渠道内近期发布的 5 至 10 篇文章进行对比，分析它们在问句、对照句、祈使句等结构上的相似度，避免连续套用相同的句式模版。

## 开头设计

开头的设计不设统一的形式。标题和正文前三段必须让零背景读者说清：谁做了什么、文章的核心判断是什么，以及继续读下去能够获得什么额外的机制或边界。事件驱动的文章，最迟应当在正文前两到三段内完成事件的锚定和分析增量的交代。

入口的设计应当服从最强证据的形态：如果是日志分析，可以从时间线切入；如果是学术论文，可以从关键结果切入；如果是产品发布，可以直接写设计选择；如果是产品演进，可以从转向或断裂处切入；如果没有独特的切入点，应当直接给出核心判断，绝不要虚构无关的场景。

**执行首屏隔离冷读测试**：隐藏设计简报、编辑对话、背景来源以及后文，只阅读标题和前三段。如果测试读者只能复述出一些陌生名称，或者说不清这些事实为什么与核心论点有关，则说明开头设计失败。

## 编辑反馈去上下文化

编辑反馈中的局部疑问是诊断信号，而不是正文的直接提纲。当收到反馈时，应当先找出其背后暴露的前置信息缺口，从调整整体理解路径的角度进行修复。

**进行隐藏编辑上下文测试**：修改后的正文应当假设读者完全没有看过编辑对话。如果正文中存在某些只有在了解该段对话后才显得自然的辩驳句、二级标题或解释说明，必须将其全部移除。

“一节内容太薄”通常意味着缺少了动态过程、明显的替代方案、适用边界，或者是机制到后果之间缺少了因果节点。Manager 应当指导 Agent 补充这些因果逻辑，绝不能靠重复结论、添加装饰性的比喻或夸大来源来凑篇幅。
